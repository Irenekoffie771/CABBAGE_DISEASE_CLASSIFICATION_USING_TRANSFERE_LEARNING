# Supabase Configuration for Cabbage Doctor AI (RLS DISABLED)

This file contains the SQL schema, storage configuration, and Edge Function code required to set up the Supabase backend for the Cabbage Doctor app. 

**Note: Row Level Security (RLS) is disabled in this configuration for easier testing/development. For production, it is highly recommended to enable RLS.**

## 1. Database Schema (SQL)

Run the following script in the Supabase SQL Editor:

```sql
-- 1. Create Profiles Table
create table public.profiles (
  id uuid references auth.users on delete cascade not null primary key,
  first_name text,
  surname text,
  dob text,
  gender text,
  profession text,
  region text,
  phone_number text,
  avatar_url text,
  updated_at timestamptz default now()
);

-- Disable RLS for profiles
alter table public.profiles disable row level security;

-- 2. Create Scan History Table
create table public.scan_history (
  id bigint generated by default as identity primary key,
  user_id uuid references auth.users on delete cascade not null,
  disease_name text not null,
  confidence float8 not null,
  description text,
  treatment text,
  image_url text,
  is_leaf boolean default true,
  created_at timestamptz default now()
);

-- Disable RLS for scan_history
alter table public.scan_history disable row level security;

-- 3. Create Schedules Table
create table public.schedules (
  id bigint generated by default as identity primary key,
  user_id uuid references auth.users on delete cascade not null,
  activity text not null,
  date_time timestamptz not null,
  is_completed boolean default false,
  created_at timestamptz default now()
);

-- Disable RLS for schedules
alter table public.schedules disable row level security;
```

## 3. Edge Function: `cabbage-doctor`

Deploy this function using the Supabase CLI (`supabase functions deploy cabbage-doctor`). You will need a Google Gemini API Key.

**`index.ts`**
```typescript
import { serve } from "https://deno.land/std@0.168.0/http/server.ts"
import { GoogleGenerativeAI } from "https://esm.sh/@google/generative-ai@0.1.1"

const corsHeaders = {
  'Access-Control-Allow-Origin': '*',
  'Access-Control-Allow-Headers': 'authorization, x-client-info, apikey, content-type',
}

serve(async (req) => {
  if (req.method === 'OPTIONS') {
    return new Response('ok', { headers: corsHeaders })
  }

  try {
    const body = await req.json().catch(() => ({}));
    const prompt = body.prompt || "Hello";
    
    console.log(`Received prompt: ${prompt}`);

    const apiKey = Deno.env.get('GEMINI_API_KEY');
    if (!apiKey) {
      throw new Error("GEMINI_API_KEY is not set in Supabase Secrets");
    }

    const genAI = new GoogleGenerativeAI(apiKey)
    const model = genAI.getGenerativeModel({ model: "gemini-pro" })

    const fullPrompt = `You are an expert Agricultural AI assistant specializing in cabbage farming. 
    A farmer is asking: "${prompt}". 
    Provide a concise, helpful, and professional answer. 
    If they ask in Twi, respond in Twi if possible, otherwise English is fine.`

    const result = await model.generateContent(fullPrompt)
    const response = await result.response
    const text = response.text()

    return new Response(
      JSON.stringify({ reply: text }),
      { headers: { ...corsHeaders, 'Content-Type': 'application/json' } }
    )
  } catch (error) {
    return new Response(
      JSON.stringify({ error: error.message }),
      { status: 500, headers: { ...corsHeaders, 'Content-Type': 'application/json' } }
    )
  }
})
```

**Environment Variables:**
Set `GEMINI_API_KEY` in your Supabase project dashboard under **Settings > Edge Functions**.
